# EvalBounty — Black Box Bazaar (B@B Fa'26 technical take-home)

A sealed marketplace on **Ethereum Sepolia** where autonomous agents buy and sell **fresh AI
evaluation tasks** that the buyer cannot inspect before paying (looking = contamination). This file
is the architecture reference for anyone (human or Claude) working in this repo.

## Mechanism in one paragraph

Buyer posts a **bounty** (domain, N tasks, k-sample, pinned weak/strong model ids, difficulty band
in bps, runs, tolerance, runParamsHash) and escrows the reward. Seller **commits** a Merkle root over
the tasks + keccak of the full bundle and posts a bond ≥ 50% of the reward. The hash of the **next
block** picks k task indices; the seller must **reveal** exactly those with Merkle proofs (no
cherry-picking; a 30%-junk bundle survives k=4 only 24% of the time). Buyer approves or rejects the
sample (subjective, never slashes). Seller **delivers** the bundle encrypted to the buyer's X25519
key (ciphertext in the event log). Buyer decrypts, checks commitment + root, **reruns the claims**
(weak ≤ max, strong ≥ min, null ≤ max, ± tolerance) and accepts or **disputes** (bond + arbitration
fee). An **ERC-792 arbitrator** reruns and rules; timeouts on every step keep funds live. Payouts
are pull-payments. Reputation counters accrue on-chain.

## Contract state machine (EvalBounty.sol)

```
Open ─commit(bond)─▶ Committed ─revealSample(proofs)─▶ Sampled ─approveSample─▶ Approved ─deliver(ct)─▶ Delivered ─accept─▶ Settled
  ▲                    │ withdrawCommit (free before sample block,   │ rejectSample (bond back, rep mark)      │ dispute(bond+fee) ─▶ Disputed ─rule(1)─▶ Settled
  │                    │  10% penalty after; finalize after 256 blks)│ finalize past approveBy (bond back)     │ finalize past verifyBy → Settled     ─rule(2)─▶ Refunded
  └────────────────────┴────────────────────────────────────────────┴── finalize past deliverBy (bond slashed to buyer)          ─rule(0)/finalize past ruleBy─▶ split
cancelBounty: Open → Cancelled
```

Rulings follow ERC-792: 0 = refused (50/50 split, bonds returned), 1 = seller, 2 = buyer.
Every payout credits `pending[addr]`; `withdraw()` is `nonReentrant`. Owner params: feeBps 200,
minSellerBondBps 5000, disputeBondBps 5000, abandonPenaltyBps 1000; windows are constructor args.

Sample rule (identical in Solidity and TS): `idx = keccak256(abi.encode(blockhash(sampleBlock), id, nonce)) % N`,
nonce++ until k distinct. Leaf = `keccak256(bytes.concat(keccak256(abi.encode(index, keccak256(taskBytes)))))`.

## Design decisions and why (defend these)

- **Vertical = model evaluations.** "Can't inspect before paying" is literal: a benchmark loses value
  once seen (contamination). Participants: eval builders (sellers), labs/deployers (buyers).
- **Buyer-declared, machine-checkable value.** Difficulty band on pinned models is reproducible by
  anyone with the bundle; meaningfulness is *sampled*, secrecy after sale is *reputational*. The
  contract only enforces what it can check.
- **Commit → blockhash-chosen sample → reveal with Merkle proofs.** Seller can't cherry-pick.
  Grinding (commit, peek, walk away, recommit) is priced: 10% bond penalty once the sample block passed.
- **Ethereum Sepolia L1, not an L2.** Sampling relies on `blockhash(sampleBlock)`. Arbitrum's docs
  call its blockhash "cryptographically insecure, pseudo-random", `block.number` is an L1 estimate and
  `prevrandao` is constant 1 — the mechanism would be weaker there.
- **Optimistic verification (FairSwap philosophy), not ZK.** The predicate "model X scores ≤ Y" cannot be
  evaluated by a contract or circuit; cheap happy path, reruns only on dispute.
- **ERC-792 arbitration interface.** Arbiter is a separate contract; swapping in a Kleros court is one
  `setArbitrator` call. ERC-1497 events make disputes legible to generic tooling.
- **Tolerance ≥ 2·SE.** Reruns are noisy on real models; SE from resampling (Miller 2024). Mock provider is
  deterministic so the demo reproduces exactly.
- **Timeouts everywhere + 50/50 split if the arbiter is offline.** No party can lock funds.
- **Arbitration is pluggable and the single-key arbiter is the weak one.** `CommitteeArbitrator` (ARBITRATION.md) removes
  buyer influence over the judge (sortition by future blockhash) and gives judges stake to lose; `setArbitrator` switches a
  live market. `deploy-contracts -- --committee [--switch]`, jurors via JUROR_KEYS + `pnpm jurors`, story `committee` in e2e/demo.
- **Reputation does work off-chain first.** The buyer reads `sellerRep` before judging a sample and rejects on record
  when losses exceed successes (`assessSellerRecord`, env-tunable). On-chain reputation-scaled bonds are the next step
  (contract change); say plainly that per-address reputation is rotatable and the bond covers each single trade.
- **Parallels, not dependencies:** ERC-8183 (client funds → provider submits → evaluator completes/rejects
  → expiry) matches our lifecycle shape; ERC-8004 registries exist on Sepolia (Identity
  0x8004A818BFB912233c491871b3d84c89A494BD9e, Reputation 0x8004B663056A597Dffe9eCcC1965A193B7388713) — optional bonus.

## Configuration and interoperability (no deployment-specific hard-coding)

- Chain, RPC, addresses, providers, domains and budgets are env vars (README → Configuration). `chain()` accepts any
  viem chain name or id; explorer URLs come from the chain definition. Never add a Sepolia/Etherscan literal to code.
- Model calls route per model id (`vendorForModel`); `MODEL_PROVIDER=mock` forces the mock for tests/e2e.
- Keys are derived, not stored: buyer per-bounty key = BLAKE2b(wallet secret, `evalbounty/v1/buyer/<chainId>/<contract>/<txNonce>`),
  recoverable from the BountyCreated tx; arbiter key = BLAKE2b(wallet secret, `evalbounty/v1/arbiter/<chainId>/<arbiterAddr>`),
  self-registered via `setArbiterPubKey`. `agents/state/` is a cache plus the seller's in-flight bundle (which contains its
  measurement and therefore cannot be re-derived).
- Dashboard config: URL query > build-time `config.js` (`dashboard/build-config.mjs` from Vercel env) . Events are fetched in
  chunks, incrementally, and cached in localStorage per (chain, contract).
- `PROTOCOL.md` is the contract for third-party agents: formats, hashing, sampling, encryption, evidence, the v1 run-params constant.

## Secrets and spend (Shaunik's OpenAI credits)

- Keys live only in `agents/.env` (gitignored, mode 600), entered via `scripts/set-keys.sh`. The dashboard is
  static and ships no keys; `scripts/check-no-secrets.sh` must pass before any push or Vercel deploy.
- Only the locally running buyer/arbiter agents call paid models. The one spend vector is a stranger
  committing to an open bounty while the buyer *loop* is running (the buyer then reruns claims on their
  delivery, ~200 calls). Mitigations: per-process call budget, prefer the scripted `demo` over long-running
  loops when not recording, small N/runs in `defaultBuyerConfig`.
- Deployed: EvalBounty 0x6b7f34fa4229aa9545b08c47d187415505c0e7a8, CentralizedArbitrator
  0x5d16caa1e9789a996839aa44a4167b574b887653, Sepolia block 11679290; CommitteeArbitrator 0x522a3853bae72170be0dca60d141329bc5afd7f0
  (minStake 0.0005, fee 0.0001, panel 3, windows 600s). The live market points at the committee since bounty #11, so
  disputed demo stories need JUROR_KEYS set; the demo seats the panel itself, loop-mode agents need `pnpm jurors`.

## Known limitations (say them out loud)

The contract enforces delivery and whether the listed claims hold. It does **not** verify that tasks are
useful beyond the sample, that they stay secret after sale, or that the single bonded arbitrator is honest
(production: committee / TEE / attested reruns). Blockhash randomness is fine at demo stakes only.
Ciphertext in calldata caps bundle size (~tens of KB); production would post a CID + hash.

## Conventions

- **Commit early and often.** Make a local commit after every coherent unit of work: a file group that
  compiles, a test suite that goes green, a script that runs, a doc section. Never leave more than
  ~15 minutes or ~200 changed lines uncommitted; a crash, a bad edit or a context reset must lose at
  most a few minutes. Use conventional-commit headers (`feat(scope):`, `fix(scope):`, `docs:`, ...)
  with a short "why" body. Commits are cheap and reversible; uncommitted work is not. Push after each
  working session once the remote is authorised (Shaunik has to OK pushes/publishing the first time).

- Never re-serialize bundle bytes: hash what you received. Use RFC 8785 for anything you hash from a value.
- Any change to a contract: `forge build && pnpm --filter agents gen-abi && forge test`.
- Keep Solidity and TS sample rules in lockstep; `test/Fixtures.t.sol` + `test/merkle.test.ts` guard this.
- Secrets live only in `agents/.env` and `agents/state/` (both gitignored). Burner keys, Sepolia only.
- Agent logs are the video's narration: every decision is one plain-English line via `log(who, msg)`.
